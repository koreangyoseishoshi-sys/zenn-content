1つのAIに企画から執筆・事実確認まで全部投げる——最初は速い。でも**必ず壁にぶつかります**。品質が安定しない、事実誤認が混じる、修正が延々と続く。答えは「賢いAI1体」ではなく、**AIを"分業"させること**でした。

医療機関の総務課で医療DXを進めている非エンジニアです。副業的に運営している情報ブログの記事制作を、**Obsidianを司令塔（SSoT）に複数のAIを"役割分担"させて回しています**。この記事では、その「制作ライン」の設計を共有します。

> ポイントは「1つのAIに全部やらせない」こと。**企画・執筆・事実確認・実装を別々のAIに分け、人間は"承認"に専念する**。工場のラインに近い発想です。

## なぜ1人＋1AIでは詰まるのか

ブログ記事1本には、実は多くの異なる作業が詰まっています。

- テーマ企画・キーワード設計
- 本文執筆
- **事実確認（法律・数値・公式情報）**
- 図解サムネ作成
- WordPressへの投稿・カテゴリ設定
- SNS告知

これを1人（＋汎用チャット1つ）でやると、毎回コンテキストを説明し直し、品質もブレます。そこで **「誰が・何を・いつやるか」を固定**しました。

## 役割分担（これが全体像）

| 主体 | 役割 |
|---|---|
| **司令塔AI（Opus）** | 企画・方針・分配・レビュー・設計 |
| **執筆AI（Sonnet）** | 本文ドラフト・SNS文・整形 |
| **一次資料AI（agy）** | ファクトチェック・**最新の公式資料/PDFを探して特定** |
| **実装AI（Codex）** | 画像のPNG化・スクショ撮影・WordPress下書き投稿 |
| **人間（自分）** | 承認・公開・外部認証 |

肝は **「一次資料を"探す"のと、それを"記事に組み込む"のを別のAIに分ける」** ところ。調査が得意なAIと、実装が得意なAIは違うからです。

## 制作フロー（1本の流れ）

```
企画(司令塔) → 本文ドラフト(執筆AI) → 事実確認/公式PDF特定(一次資料AI)
→ 図解サムネ・スクショ(実装AI) → WordPress下書き投稿(実装AI)
→ ★人間が承認して公開 → SNS告知(執筆AI)
```

★の「人間の承認」だけは絶対に自動化しません。**AIは下書きまで、公開判断は人間**。法律系の情報を誤って拡散しないための安全弁です。

## 品質を上げている2つの工夫

### ① シリーズ設計で「回遊」を作る

記事を単発で出さず、テーマごとに**シリーズ化**します。

- 各シリーズに「まとめ記事（入口）」を置く
- 各記事の冒頭に「①②③（今ここ）」の目次
- 記事末に「次はこちら →」＋まとめ記事へのリンク

これで読者が次の記事へ進み、滞在時間が伸びる。同時に、同テーマの記事が相互リンクで固まることで、検索エンジンに「この分野の専門サイト」と認識されやすくなります（トピッククラスター）。**外部バナーで人を"外に出す"より、シリーズで"中に留める"方が効く**、という考え方です。

### ② 一次資料は「最新の公式PDF」を引用する

制度・法律・お金まわりの記事では、**Webページのスクショではなく、最新の"公式PDF文書"（運用要領・告示・リーフレット等）を探して引用**します。

- 公式PDFの方が、HTMLページより一次資料としての権威・鮮度が高い
- 「最新のPDFを探して出典付きで引用する」こと自体が、量産まとめ記事との差別化になる

ここで効くのが役割分担で、**「最新の公式PDFを探す」のは一次資料AI**、**「そのPDFの該当ページを撮って記事に組み込む」のは実装AI**、と工程を分けています。

## 安全弁（やらないこと）

- **公開の自動化はしない**（下書きまで。公開は人間）
- 法律・数値記事は**事実確認を通してからでないと公開しない**
- 出典のない主張・断定はしない
- 秘密の鍵（APIトークン等）はSSoT（Obsidian）に置かない

## まとめ

- 記事制作を**「企画／執筆／事実確認・一次資料／実装」に分業**し、人間は承認に専念
- Obsidianを**唯一の正（SSoT）**にして、各AIはそこのルールに従って動く
- **シリーズ設計**で回遊・専門性を、**公式PDF引用**で信頼性を積む

非エンジニアでも、「1つのAIに全部やらせる」発想を捨てて**役割分担のライン**を組むと、品質と継続性が一気に上がります。次は各AIの具体的な連携（Obsidianのタスク受け渡し）を書く予定です。
