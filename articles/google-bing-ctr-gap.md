Search Console を開いたら、先月より CTR（クリック率）が下がっていた。Google の CTR が Bing の半分しかない。そう見えたとき、すぐにタイトルや説明文を直したくなります。

ところが CTR は、**全体で比べると、中身のどの部分でも勝っている側が「負けている」ように見える**ことがあります。統計ではシンプソンのパラドックスと呼ばれる現象です。成約率（CVR）や A/B テストでも同じことが起きます。

この記事では、なぜそうなるのか、どうすれば見分けられるのか、どう比べ直せばいいのかを整理します。

## 中身ではすべて勝っているのに、全体では負ける

2つのサイトの検索のクリック率を比べます。検索結果の上位に出たときと、下のほうに出たときに分けて数えました。

| | 上位に出た表示 | 上位のクリック率 | 下位に出た表示 | 下位のクリック率 | **全体のクリック率** |
|---|---:|---:|---:|---:|---:|
| サイトA | 1,000 | **10.0%** | 9,000 | **1.0%** | 1.9% |
| サイトB | 4,000 | 8.0% | 6,000 | 0.8% | **3.7%** |

上位でも下位でも、A のほうがクリック率は高い。それなのに、全体ではAが B の半分しかありません。

計算は間違っていません。

- A：(1,000×10% + 9,000×1%) ÷ 10,000 = 190 ÷ 10,000 = 1.9%
- B：(4,000×8% + 6,000×0.8%) ÷ 10,000 = 368 ÷ 10,000 = 3.7%

## なぜそうなるのか：全体の割合は「重み付きの平均」

全体の割合は、中身の割合を**それぞれの量で重み付けした平均**です。

```
全体の割合 = Σ（その層の量の比率 × その層の割合）
```

A は表示の9割が「下位」です。下位はもともとクリック率が低い層なので、全体の平均は下位の 1% に引っぱられます。B は4割が「上位」なので、上位の 8% に引っぱられます。

つまり全体の差は、

- **中身の割合の差**（同じ層どうしで比べてどうか）
- **構成の差**（どの層にどれだけの量があるか）

の2つが混ざったものです。そして、構成の差のほうが大きいと、中身の差と逆向きの結論が出ます。

## どこで起きるか

量の配分が違うものを、全体の割合で比べると起きます。たとえば次のような場面です。

| 比べているもの | 構成が違う中身 |
|---|---|
| 検索エンジンごとのクリック率 | 出ているページ、平均順位 |
| 先月と今月のクリック率 | 新しく増えたページ（最初は順位が低い） |
| 広告の経路ごとの成約率 | 新規と既存の客の割合 |
| A/B テストの成約率 | スマホとパソコンの割合が両方で違うとき |
| 部署ごとの合格率・達成率 | 難しい案件の割合 |

全体の数字が動いたとき、「中身が良くなった・悪くなった」のか、「構成が変わっただけ」なのかを分けないと、直す場所を間違えます。

## 見分け方1：層をそろえて比べる

まず、結果に効いていそうな軸で層に分けて、**同じ層どうし**で比べます。検索のクリック率なら、いちばん効くのは順位です。

```python
import csv
from collections import defaultdict

def band(pos):
    p = float(pos)
    if p <= 3.5:  return "1-3"
    if p <= 10.5: return "4-10"
    if p <= 20.5: return "11-20"
    return "21+"

def by_band(path, imp_col, clk_col, pos_col):
    agg = defaultdict(lambda: [0.0, 0.0])
    for row in csv.DictReader(open(path, encoding="utf-8-sig")):
        a = agg[band(row[pos_col])]
        a[0] += float(row[imp_col])
        a[1] += float(row[clk_col])
    return agg

g = by_band("google.csv", "impressions", "clicks", "position")
for b, (imp, clk) in sorted(g.items()):
    print(b, int(imp), f"{clk/imp:.2%}")
```

注意が1つあります。割合は**行ごとの割合を単純に平均してはいけません**。表示1回でクリック1回の行（100%）と、表示1,000回でクリック0回の行（0%）を平均すると50%になってしまいます。必ず、層ごとに分子と分母を足してから割ります。

## 見分け方2：差を「中身」と「構成」に分ける

層ごとに見ると数字が多くて判断しにくいときは、全体の差を2つに分解します。

```
全体の差 = 中身の効果 + 構成の効果

中身の効果 = Σ Aの比率 × (Aの割合 − Bの割合)
構成の効果 = Σ (Aの比率 − Bの比率) × Bの割合
```

上の例で計算すると、

| | 値 |
|---|---:|
| 中身の効果 | +0.38 ポイント（A のほうが良い） |
| 構成の効果 | −2.16 ポイント（A は低い層に偏っている） |
| 合計（全体の差） | −1.78 ポイント |

A の本当の課題は「クリックされにくいこと」ではなく、「下位にしか出ていないこと」だと分かります。打ち手は、タイトルの書き方ではなく順位を上げることです。

```python
def decompose(a, b):
    """a, b: {層: (分母, 分子)}。全体の差を中身と構成に分ける"""
    na = sum(v[0] for v in a.values()); nb = sum(v[0] for v in b.values())
    rate = mix = 0.0
    for k in set(a) | set(b):
        wa = a.get(k, (0, 0))[0] / na; wb = b.get(k, (0, 0))[0] / nb
        ra = a[k][1] / a[k][0] if k in a and a[k][0] else 0.0
        rb = b[k][1] / b[k][0] if k in b and b[k][0] else 0.0
        rate += wa * (ra - rb)
        mix  += (wa - wb) * rb
    return rate, mix

a = {"上位": (1000, 100), "下位": (9000, 90)}
b = {"上位": (4000, 320), "下位": (6000, 48)}
print(decompose(a, b))  # (0.0038, -0.0216)
```

## 層の切り方で、結論はまた変わる

層をどう切るかで、結論が変わることもあります。順位で切ったら差が消えたのに、ページで切ると別の偏りが見える、ということは普通に起きます。

切る軸は、**結果を生む仕組み**から選びます。

- クリック率なら：順位（見られる確率を決める）、ページ（何を探している人に出るか）
- 成約率なら：新規か既存か、どの経路から来たか
- 迷ったら：「この軸で量の配分が大きく違うか」を先に見る。配分が同じなら、その軸は全体の比較をゆがめていません

層を細かく切りすぎると、1つの層の量が小さくなり、偶然の差が大きく見えます。クリックが数件しかない層の割合は、ほとんど当てになりません。

## 例：検索エンジンごとのクリック率

私のサイトで、Google のクリック率が Bing の半分（1.9% と 3.8%）になっていたことがあります。全体だけを見ると「Google での見え方が悪い」と考えたくなります。

層に分けると、中身はこうでした。

- 平均順位が違った（Google 9.4位、Bing 6.1位）
- Bing の表示の4割強が、Bing でだけ上位に出る2本の記事だった。その2本を除くと、Bing は 2.5% まで下がった
- 同じページ・ほぼ同じ順位で比べると、差はずっと小さく、逆転するページもあった

差の大半は構成の差で、打ち手は「タイトルを直す」より「Google で出ていない記事がなぜ出ないかを調べる」でした。

## まとめ

| | |
|---|---|
| 何が起きるか | 中身ではすべて勝っている側が、全体の割合では負けて見える |
| なぜか | 全体の割合は重み付きの平均。量の配分（構成）が違うと、平均が引っぱられる |
| 見分け方 | 結果を生む軸で層に分け、同じ層どうしで比べる。差を中身と構成に分解する |
| 気をつけること | 行ごとの割合を平均しない。層を細かく切りすぎない。切る軸は仕組みから選ぶ |

全体の割合が動いたら、直す前に「中身が変わったのか、構成が変わったのか」を1回分けてみてください。
